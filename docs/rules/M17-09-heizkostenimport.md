# M17-09 Heizkostenimport des Messdiensts (heating_cost_import)

| Field | Content |
| --- | --- |
| ID | M17-09 |
| Title | Externe Heizkostenabrechnung des Messdiensts als eigene Entität mit Prüfung vor der Übernahme (H01) |
| Scope | Betriebskostenabrechnung Miete und SEV (`mhvp.billing`). Ein Import je Messdienstabrechnung: Originaldokument, Messdienst (Kontakt und Name), Abrechnungszeitraum, Belegsumme, Nutzermapping (Nutzernummer des Messdiensts zu Einheit und Mietvertrag, ohne Vertrag Leerstand der Einheit), Kostenbestandteile je Nutzernummer (Heizung Grundkosten, Heizung Verbrauchskosten, Warmwasser Grundkosten, Warmwasser Verbrauchskosten, CO2-Anteil Vermieter, CO2-Anteil Mieter). Status `draft`, `checked`, `applied`. Nicht umgesetzt: Einlesen des ARGE HeiWaKo D-Formats und anderer Messdienstformate (nur CSV mit Spaltenzuordnung durch den Bearbeiter), automatische Nutzerzuordnung |
| Source status | Anhang C R11 (HeizkostenV) und R15 (CO2KostAufG) nur über die bestehende Regel M17-02: die CO2-Prüfung ruft `heating_calc.co2_split` mit der Stufentabelle aus `heating_rule_table` bzw. der Code-Fassung (Status `zu_pruefen`) auf; es gibt keine eigene Stufenlogik. Dass der CO2-Vermieteranteil nicht auf den Mieter umgelegt wird, ist Annahme A-M17-09-01 (Entscheidung offen, OPEN_QUESTIONS M17-09-01). Ausgabe der Abrechnung bleibt hinter G3 |
| Acceptance case | Eigener Modellfall (Anhang D nennt keine Beträge): drei Nutzer 1.300,00, 350,00 und 650,00 EUR, Belegsumme 2.300,00 EUR, CO2-Kosten 100,00 EUR, 3.400 kg auf 100 m² ergibt 34 kg/m² und 50 Prozent Mieteranteil, Vermieteranteil 50,00 EUR; Übernahme 1.270,00 + 345,00 + 635,00 = 2.250,00 EUR. Tests `apps/api/tests/unit/test_m17_09_heating_import.py`, `apps/api/tests/integration/test_m17_09_heating_import.py` |
| Checks (blocking) | Summe der vier Kostenbestandteile gleich Belegsumme (centgenau); CO2-Anteile je Nutzer nicht größer als dessen Heizkosten; Summe der CO2-Anteile gleich CO2-Kosten laut Beleg (falls angegeben); Originaldokument vorhanden; jede Nutzernummer einer Einheit des Objekts zugeordnet, Vertrag ist Mietvertrag dieser Einheit; CO2-Aufteilung nicht im Prüfstatus und Vermieteranteil laut Messdienst weicht höchstens einen Cent je Nutzer vom Stufenmodell ab; bei möglicher Doppelerfassung (Rechnung desselben Ausstellers mit überlappendem Leistungszeitraum im Rechnungsbuch oder weiterer Import desselben Messdiensts und Objekts mit überlappendem Zeitraum) nur mit Begründung |
| Apply | Nur Status `checked`, Abrechnung im Entwurf, gleiches Objekt und gleicher Zeitraum, keine eigene Heizkostenposition (M17-02) und kein weiterer übernommener Import in der Abrechnung. Ergebnis: eine externe Heizkostenposition mit `external_amounts` je Nutzer (Kostensumme abzüglich CO2-Vermieteranteil). Danach ist der Import gesperrt |
| Implementation | `mhvp.billing.heating_import`, `mhvp.billing.heating_import_routers` (`/api/v1/billing/heating-cost-imports`, `/{id}`, `/{id}/mapping`, `/{id}/rows`, `/{id}/csv`, `/{id}/check`, `/{id}/apply`), Modell `HeatingCostImport`, Migration 0292 |
| Change reason | Lückenliste 30.09.2026 M17-09, Welle 5 Paket T06 (01.10.2026) |
