# M21 Portal Mieter und Eigentümer / M22 Portal Dienstleister: plan and result

Status: API implemented; portal UI implemented in `apps/web-portal` (2026-09-25). Source:
MASTER-PROMPT 6.9.6, 14, 18.

* Package `mhvp.portal`, migration 0020: portal_account (invitation with hashed one time code),
  access_grant (6.9.6), portal_change_request (encrypted payload). Documents may link to a legal
  entity (GdWE documents).
* Management: invite, derive grants, decide proposals. Portal: me, documents and download
  through the same matrix, tickets and comments, change and meter proposals, account statement.
* Providers (M22): own work orders, decline, quote with upload, appointment after approval,
  execution report, invoice submission as proposal.
* Test: `tests/integration/test_m21_portal.py` (owner, tenant, other GdWE, SEV-like contract
  file, hidden visibility, provider isolation, no CRM access). Open: M21-01 to M21-03, M22-01.
* Portal UI (`apps/web-portal`): role aware start page under `/start` (tenant/owner tiles vs.
  provider tiles, `src/components/portal/StartTiles.tsx`), `/dokumente` (list, download via
  `/api/portal-files/portal/documents/{id}/download`), `/meldungen` (list with history, new
  Schadensmeldung with optional photo upload, comments; `/meldungen/[id]`), `/konto` (open
  items, `1.234,56 EUR` and `TT.MM.JJJJ`), `/zaehlerstand` (reading as a proposal) and `/daten`
  (change request form for address, phone, e-mail, bank account). Navigation in
  `src/app/(portal)/layout.tsx` is role aware and mobile usable (16px gutters, no horizontal
  scroll). BFF allowlist (`src/app/api/bff/[...path]/route.ts`,
  `src/app/api/portal-files/[...path]/route.ts`) extended for every route used. The ticket
  create endpoint has no field to link an uploaded photo to the ticket; the uploaded document id
  is therefore appended to the ticket description as a note for the office (see
  `NewTicket.tsx`) — a real attachment link would need an API change (open point). Every action
  that touches money or the contract is shown as "Vorschlag, wird von der Verwaltung geprüft."
  Vitest: `StartTiles.test.tsx` (role switch), `NewTicket.test.tsx` (create with validation),
  `WorkOrderDetail.test.tsx` (decline with confirmation), BFF allowlist tests in
  `route.test.ts`/`route.test.ts` (portal-files). `pnpm -s exec tsc --noEmit`,
  `pnpm -s exec eslint src --max-warnings 0` and `pnpm -s exec vitest run` pass (23 tests); two
  pre-existing `tsc` errors in `src/app/api/session/{login,mfa/verify}/route.ts` are unrelated to
  this change and were left untouched.
