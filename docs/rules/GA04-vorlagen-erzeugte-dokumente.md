| Acceptance case | None in annex D. Tests `apps/api/tests/integration/test_aa05_templates_generated.py` (placeholders as dotted paths without local names, 422 for unknown context type, 403 without `tenant_settings:update`, 404 for unknown letterhead template, context filter, refusal of a context the template does not allow, provenance row with template, version, context and recipient, tenant separation, work order reference, ranking of embedded examples with cut-off) |
| Implementation | A template without context types is unrestricted. A letter with property, unit or contract is refused (422) when the template lists context types without it; the contact is always the recipient. `generated_document` has one row per stored document (unique per tenant and document): template id, code and version (or the name of the built-in letter in `template_code`), context type and id (contract, unit, property, else the recipient), recipient contact, dispatch id (set by `record_dispatch`); channel and evidence are read from the dispatch row. Listing respects the legal entity and property scope of the documents. Learning examples are embedded by the existing index job (kind `ai_example`); the gateway orders the few shot examples by cosine distance to the input when embeddings exist and falls back to recency otherwise |
