# M23-05 Google-Kalender: Einladungen nur nach Bestätigung, kein stiller externer Überschreib (Produktschutz)

| Title | Kalendertermine werden ohne Einladung an externe Teilnehmer angelegt; Versand nur nach ausdrücklicher Bestätigung; ein extern geänderter Termin wird als abweichend markiert, nie automatisch überschrieben |

## Regeln

- Ein Termin, der mit Teilnehmern angelegt wird (aus Ticket, Übergabeprotokoll oder manuell),
  wird bei Google immer mit `sendUpdates=none` angelegt beziehungsweise ohne Teilnehmerliste
  im Event-Body. Die vorgesehenen Teilnehmer werden nur auf dem `calendar_event`-Datensatz
  gespeichert (`status = "draft"`).
- Der Versand der Einladung ist ein eigener, expliziter Schritt (`POST
  .../invite`, Feld `confirm: true`). Ohne Bestätigung (422) und ohne hinterlegte Teilnehmer
  (422) wird nichts gesendet. Der Aufruf setzt `sendUpdates=all`, vermerkt
  `invite_confirmed_by`/`invite_confirmed_at` und setzt `status = "invited"`.
- Eine Absage (`DELETE .../google/{source}/{event_id}`) benachrichtigt externe Teilnehmer
  (`sendUpdates=all`) nur, wenn zuvor tatsächlich eingeladen wurde (`status == "invited"`);
  sonst `sendUpdates=none`.
- Der Lesepfad vergleicht bei jedem Abruf das Google-`etag` mit dem zuletzt synchronisierten
  Wert auf `calendar_event`. Weichen sie ab, gilt der Google-Stand als aktuell für die
  Anzeige (`title` etc. aus Google), der CRM-Datensatz wird als `is_stale = true` markiert;
  es wird nichts automatisch überschrieben. Ein `PATCH` auf einen als `is_stale` markierten
  Termin wird mit 409 abgelehnt, bis der Google-Stand geprüft wurde.
- Diese Regel ist Produktschutz, keine gesetzliche Pflicht: sie verhindert ungewollte
  E-Mails an Dritte und den stillen Verlust externer Änderungen, ersetzt aber keine
  rechtliche Prüfung der jeweiligen Terminkommunikation.
