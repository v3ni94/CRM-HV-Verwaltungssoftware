# M3 Kontakte: plan and result

Status: backend and CRM UI done (contact roles and SEPA mandate added 25.09.2026, version 1.11.0). Source: MASTER-PROMPT 6.1, 16, 18 (M3), 7.11 S06.
Acceptance: CRUD via API and UI; duplicate proposal; full text search; export per contact
(DSGVO access).

## Decisions

* Tables per 6.1: `contact`, `contact_address`, `contact_phone` (E.164), `contact_email`,
  `contact_identifier`, `contact_bank_account` (IBAN encrypted per tenant, last four
  characters in clear, keyed fingerprint for exact duplicate matching), `contact_type`,
  `contact_tag`, `contact_tag_link`, `contact_note`, `contact_relation`, `party`,
  `party_member`, `consent`. All with RLS (migration 0003). `portal_account` follows with the
  portal (M21), not in advance.
* Contracts will reference `party`, never a contact (6.1). Party names are generated neutrally
  ("Anna und Ben Paar"); a shared last name is not treated as proof of marriage.
* Validation: IBAN ISO 13616 mod 97 with country lengths for DE/AT/CH/NL/BE/FR/LU/IT/ES,
  phone numbers valid per libphonenumber with default region DE, e-mails lower case.
* Search: `search_text` maintained by the service (names, company, e-mails, phone numbers,
  IBAN suffixes, cities), `tsvector` generated column (simple config, prefix queries) plus
  trigram index; `GET /search` is the global search (contacts now, further entities later).
* Duplicates: exact e-mail (0.95), IBAN fingerprint (0.95), phone (0.9), name trigram
  similarity (up to 0.85); proposal only, no automatic merge.
* Updates are full replacements with `If-Match`; audit log stores field changes.
* Deletion is soft (`deleted_at`); hard deletion follows the retention profiles (6.9.5).
* DSGVO export: JSON with contact data, decrypted IBAN of the data subject, notes, consents,
  relations as references, party name and own role, processing log; `review_required = true`
  because notes can contain data of third parties.
* Permissions `contacts:*`; system roles extended; `python -m mhvp.platform.sync_roles` runs
  in the migrate job so existing tenants receive new template permissions.

## Result (backend)
