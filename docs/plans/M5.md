# M5 Verträge: plan and result

Status: backend done (2026-09-23). Source: MASTER-PROMPT 6.3, 6.9.1, 6.9.2, 6.9.3, 6.9.11,
7.2, 18 (M5), annex A.1, A.3, E01, E02, E03, E13.
Acceptance: create a contract, change it (new version), end it; payment history; occupancy list;
SEPA overview.

## Decisions

* Tables (migration 0005, all with RLS): `contract`, `debtor_account_reservation`,
  `contract_payment`, `payment_schedule`, `sepa_mandate`, `deposit`, `deposit_movement`, and the
  tenant wide `number_sequence` (row lock per scope, gapless while transactions commit).
* One contract type with `kind = tenancy | ownership` (6.3). Per unit and kind at most one
  contract per day: GiST exclusion on `daterange(start_date, end_date, '[]')` (6.9.2).
* Creditor (`legal_entity_id`, 6.9.1, A-015): ownership belongs to the GdWE; a tenancy on a
  rental property belongs to the owner valid at the start (explicit choice if several); a tenancy
  on `hoa_with_sev` belongs to the SEV owner entity, created on demand; plain HOA properties have
  no tenancies (M5-03). The management company is never the default creditor.
* Debtor accounts per party and unit in the creditor's books, not per version (6.9.2, D15), six
  digits from 090000 to 099999 (7.2, A.1, A-013), name "Einheit Vertragspartei". Only reserved;
  postings start with M10 behind G1.
* Ownership: `title_transfer_date` required and not after the start, `benefit_burden_date`
  separate (D16), `acquisition_kind`, `special_succession_liability`. A transfer ends the old
  ownership the day before the title transfer and creates a new contract with a new debtor
  account (D15, D17); old payments stay with the seller.
* SEV only on ownership in `hoa_with_sev`; `sev_fee_debtor_party_id` defaults to the owner (E13).
* Versions: a change with an effective date closes the old version the day before and creates
  version n+1 with the same number and debtor account; payments and schedules spanning the date
  are split, later ones move. Only the latest version can be versioned.
* Payments per payment type (catalogue from A.3) with periods; a new open payment closes the
  previous open one of the same type. Plausibility: gross = net · (1 + VAT/100) within 0.01 EUR;
  negative amounts only for `rent_reduction`. No tax treatment is derived (S01).
* Termination ends payments and schedules; payments starting after the end block it.
* SEPA mandates are records with evidence (`document_id` required), creditor id with checksum,
  unique reference per creditor id, B2B only if all party members are companies (A-014). Direct
  debit needs an active mandate of the same party and creditor; revoking a mandate switches
  direct debit off. Collection stays locked until G2.
* Deposits only for tenancies, on a segregated deposit account of the landlord (D56). Movements
  are records (`review_required` until M10); payout and offset need a reason and cannot exceed
  the balance. Interest rules are open (M5-02).
* Statement status model (6.9.3, E03) as pure logic in `billing.status`; tables follow in M17/M24.
* Contacts: `PUT /contacts/{id}` keeps bank accounts when `bank_accounts` is omitted; replacing
  accounts referenced by a mandate is rejected (M5-01). The CRM form omits them on edit.

## Endpoints

`/contracts` (list with filters, create), `/contracts/{id}` (read), `/versions` (list, create),
`/termination`, `/ownership-transfer`, `/payments` (create, history over all versions),
`/schedules`, `/contracts/{id}/deposits`, `/deposits/{id}/movements`, `/sepa-mandates` (list =
SEPA overview, create), `/sepa-mandates/{id}/revoke`, `/properties/{id}/occupancy?as_of=`.
Permissions `contracts:*`; caretakers have none.

## Result

* API: ruff, mypy strict, `alembic upgrade/downgrade/check`, 173 tests passed, coverage 92.8 %
  (coverage now tracks greenlet and thread concurrency, before it undercounted async code).
* New tests: `tests/integration/test_m5_contracts.py` (rental lifecycle, versions, termination,
  occupancy, permissions; ownership transfer and SEV creditor; mandates, direct debit, deposits,
  contact edit with mandated account), `tests/unit/test_m5_rules.py` (status model D13/D14,
  amount plausibility, SEPA identifiers).
* Web: lint, typecheck, 30 CRM unit tests passed. CRM UI for contracts follows with the object
  UI; not executed in this milestone: Playwright against the API for contracts (no UI yet).
