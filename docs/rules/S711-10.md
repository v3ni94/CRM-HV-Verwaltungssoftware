# S711-10 Verzeichnis der Verarbeitungstätigkeiten: Verantwortlichkeiten, Unterauftragnehmer, Drittland

| Field | Content |
| --- | --- |
| ID | `S711-10` |
| Title | Verzeichnis von Verarbeitungstätigkeiten als Entwurf mit Rollen von GdWE, Verwalter und Betreiber je Tätigkeit, Unterauftragnehmern aus der tatsächlichen Konfiguration, Drittlandübermittlung je Anbieter und Rechtsgrundlage als Pflegefelder, Export Markdown und PDF |
| Scope | `mhvp.privacy` (`config_sources`, `register_doc`, `routers`), Tabelle `privacy_register_entry` (Migration 0388); CRM Einstellungen, Datenschutz; alle Mandanten |
| Requirement type | Fachliche Umsetzung (7.11 S06, 16); Rechtsinhalt Offene Entscheidung (V13, P17-02, AE32-01) |
| Source status | Anhang C R25 (DSGVO) nennt den Prüfumfang (Verantwortlichkeiten, Auftragsverarbeitung, Übermittlung), legt aber keine Rolle und keine Rechtsgrundlage für eine konkrete Verarbeitung fest. Deshalb belegt die Plattform keine Rolle, keine Rechtsgrundlage und keinen Drittlandstatus vor; jedes Feld startet mit "offen" und ist ein Eintrag des Betreibers nach rechtlicher Prüfung |
| Erkennung | Nur aus der tatsächlichen Konfiguration: Plattformeinstellungen (Objektspeicher, objektakte für den zugeordneten Mandanten, Tracing) und Konnektoren des Mandanten unter RLS (Gmail und Google Kalender, IMAP/SMTP-Hosts, Google Drive, Paperless-ngx, finAPI, GoCardless, KI-Anbieter, Postversand, WhatsApp, SMS-Gateway, Telefonanlage, Lexware Office). Ausgabe nur technischer Angaben (Host, Modus, Anzahl, aktiv), keine Zugangsdaten, keine Postfachadressen |
| Übernahme | `POST /privacy/register/config-sources/sync` legt fehlende Dienste als Unterauftragnehmer an: AVV `none`, Drittland `open`, rechtliche Prüfung `open`, `source_key`. Nicht aktive Dienste nur mit `include_inactive`. Bestehende Einträge: nur `source_detail` wird aktualisiert, Betreiberfelder nie überschrieben. Serialisiert je Mandant (Advisory Lock), eindeutig über `(tenant_id, source_key)` |
| Pflegefelder | Je Tätigkeit: `responsibilities` für `gdwe`, `verwalter`, `betreiber` mit `open`, `controller`, `joint_controller`, `processor`, `not_involved`; `legal_basis` (Freitext); `responsibility_note`; `processor_ids` (nur Einträge der Art Auftragsverarbeiter oder Unterauftragnehmer desselben Mandanten, sonst 422 MHVP-PRIV-0004). Je Eintrag: `third_country_status` `open`, `no`, `yes`, `third_country_countries`, `third_country_note` (Garantien). Ohne `third_country_status` gilt `third_country=true` als `yes`, sonst `open`; nur ein ausdrückliches `no` dokumentiert, dass keine Übermittlung stattfindet. Migration 0388 setzt bestehende Zeilen mit `third_country=true` auf `yes`, alle übrigen auf `open` |
| Ausgabe | Markdown (`GET /privacy/processing-records`) und PDF (`GET /privacy/processing-records/pdf`) aus derselben Blockstruktur; Prüfhinweis V13 fest; Abschnitt "Anbieter laut Konfiguration ohne Registereintrag"; Herkunft je Anbieter (manuell, aus Konfiguration, nicht mehr in der Konfiguration); offene Punkte (AVV fehlt, Drittland ungeklärt oder ohne Garantie, Rechtsgrundlage fehlt, Rolle offen, Anbieter ohne Eintrag, Einträge ohne rechtliche Prüfung) |
| Acceptance case | keiner in Anhang D; Tests `apps/api/tests/integration/test_ae32_privacy_register.py`, `apps/api/tests/unit/test_ae32_register_doc.py`, CRM `PrivacyConfigSources.test.tsx`, `PrivacyRegisterEditor.test.tsx` |
| Change reason | Prioritätenliste des Betreibers 01.10.2026 Punkt 26 (Befund S711-10, Paket AE32, Welle 16) |
