# AG07-01: Umlaufbeschluss im Eigentümerportal (technisch vorbereitet)

- **ID:** AG07-01
- **Geltungsbereich:** Umlaufverfahren (Versammlung der Art `circular_resolution`, `mhvp.hoa.portal_circular`), Portalseite Umlaufbeschlüsse, CRM Umlaufbeschluss erfassen (Portalstimmen lesend)
- **Anforderungstyp:** Fachliche Umsetzung (Abschnitt 14, Tabelle Eigentümer, Phase 4), Produktschutz (Schalter, Gate), Offene Entscheidung (Zulässigkeit der Stimmabgabe im Portal, AE31-01)
- **Quellenstatus (Anhang C):** keine neue Rechtsregel. Mehrheitsprüfung und Ergebnisfeststellung bleiben unverändert (`hoa.majority`, M25-02). Ob die Stimmabgabe im Portal die Textform erfüllt, entscheidet die Software nicht.
- **Abnahmefall:** Anhang D, WEG-Beschluss (Stimme je Einheit); Abnahme durch den Betreiber
- **Gate:** G4 (geschlossen) für die Stimmabgabe; Mandantenschalter `hoa_online_meeting_setting.portal_circular_resolution_enabled` (Standard aus)
- **Offene Fragen:** AE31-01
- **Änderungsgrund:** Befund GAF-32, Welle 18, Stand 02.10.2026

## Regeln

| Nr. | Regel | Prüfung |
| --- | --- | --- |
| 1 | Schalter aus: Liste zeigt `enabled: false` ohne Verfahren, Stimmabgabe 403 MHVP-HOA-0037, nichts wird gespeichert. | API |
| 2 | Stimmabgabe braucht G4; geschlossen ergibt 403, nichts wird gespeichert. | API |
| 3 | Sichtbar sind nur Umlaufverfahren (Status eingeladen oder durchgeführt) der eigenen Gemeinschaft mit eigenen stimmberechtigten Einheiten. | API |
| 4 | Eine Stimme je Einheit und Beschlussantrag (Kanal circular, Quelle own); eine zweite Stimme ergibt 409. Fremde Einheiten 403, Vollmachten werden hier nicht angenommen. | API |
| 5 | Nachweis je Stimme: Zeitpunkt, Portalbenutzer und SHA-256 des Antragstexts (Titel, Zeilenumbruch, Antrag). Nach Feststellung des Ergebnisses keine Stimme mehr (409). | API |
| 6 | Das CRM zeigt Portalstimmen lesend im Formular Umlaufbeschluss; die Übernahme in die Ergebnisfeststellung bleibt bei der Verwaltung. | UI |
