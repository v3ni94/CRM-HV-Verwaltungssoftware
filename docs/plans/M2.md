## Scope and decisions

| Area | Implementation |
| --- | --- |
| Platform tables (no RLS, 5.3) | `tenant`, `tenant_domain`, `app_user`, `membership`, `refresh_token`, `oidc_client`, `oidc_authorization_code`. `membership` is platform level because login must list a user's tenants before a tenant context exists (ADR 0006). The RLS guard test carries this allowlist explicitly. |
| Tenant tables (RLS) | `role`, `role_permission`, `membership_role`, `tenant_settings`, `api_key`, `release_gate_request`, `domain_event`, `audit_log`, `webhook_subscription`, `webhook_delivery`. |
| Passwords | Argon2id (argon2-cffi defaults). Length 12 to 128, no composition rules, lockout after 10 failures for 15 minutes (ASSUMPTIONS A-012). |
| 2FA | TOTP (RFC 6238, pyotp) mandatory for every CRM login (3.4: "Pflicht für Verwaltungsrollen"). Secret encrypted. |
| Tokens | Access JWT ES256, 15 min, claims `sub`, `tenant_id`, `roles`, `scopes`, `platform`; refresh tokens opaque, stored as SHA-256, rotating per family, reuse revokes the family; session list and revoke. |
| API keys | `mhvp_<prefix>_<secret>`, SHA-256 stored, scopes, expiry, last use, revoke. |
| OIDC provider | discovery, JWKS, authorize (code + PKCE S256 only), token, userinfo for registered clients. Login UI for the browser redirect follows with the CRM UI (M9); M2 authorize accepts an authenticated bearer. |
| Permissions | resource x action (`read`, `create`, `update`, `delete`, `approve`, `export`), roles per tenant with inheritance; system roles from annex A.4 seeded. M2 resources: `tenant_settings`, `members`, `roles`, `api_keys`, `webhooks`, `audit`, `release_gates`. |
| Tenant resolution | Host header against `tenant_domain`; token tenant must match (3.3). Platform admin switch is explicit, requires a reason and is recorded as event in the target tenant. |
| Encryption | `EncryptedText` with AES-256-GCM, key per scope derived by HKDF from `MHVP_MASTER_KEY` (tenant id or `platform`), scope bound as AAD and checked on decrypt (3.5). |
| Events, audit | `domain_event` and `audit_log` append-only (trigger rejects UPDATE/DELETE). Events are the outbox for webhooks. |
| Webhooks | subscriptions per tenant, HMAC-SHA256 `X-MHVP-Signature: t=<unix>,v1=<hex>` over `<t>.<body>`, retries 1 min, 5 min, 30 min, 2 h, 6 h, 24 h, manual redelivery, SSRF guard (no private targets outside dev/test), no redirects. |
| Release gates | `release_gate_request`: tenant admin requests with scope and evidence reference, a platform admin who is a different person approves; revocable; `DbReleaseGateResolver` replaces the closed default. No gate is opened by seeds. |
| Seeds | `mhvp/tenant/seeds/*.json` from skills `hvm-ci` and `ci-timo-mueller-einzelunternehmen`; missing values `TODO`; `make seed`. V14 release stays open. |

Out of scope: UI for login and administration (M9), SSO clients of existing tools (after V1).

## Tests

RLS isolation for every new tenant table (guard), login with lockout and TOTP, refresh rotation
and reuse detection, API key scopes, permission denial (D50 basis), host/token mismatch,
platform switch audit, encryption scope mismatch, append-only events, webhook signature,
retry schedule, SSRF refusal, delivery against a local HTTP server, gate four eyes rule,
seeds idempotent with the two tenants.
