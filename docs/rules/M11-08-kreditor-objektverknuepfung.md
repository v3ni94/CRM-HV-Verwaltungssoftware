# M11-08 Kreditoren je Objekt: Kontakt aus dem Bankumsatz, Verknüpfung mit dem Objekt, IBAN nur im Vier-Augen-Prinzip

| Field | Content |
| --- | --- |
| ID | `M11-08` |
| Title | Einrichtung in drei Schritten (Bankzugang, Konto, Objekt und Kontoart mit abgeleitetem Rechtsträger), Kreditor anlegen aus einem Bankumsatz als Kontakt mit Rolle Dienstleister, Verknüpfung Kreditor mit Objekt (Gewerk, Beginn, Quelle), Nachziehen aus vorhandenen Buchungen und Rechnungen |
| Scope | Domänen `properties` (Tabelle `property_creditor`, Migration 0240, RLS je Mandant), `contacts` (Rolle `dienstleister`, Bankverbindung `pending`), `banking` (Zuordnung bestehender Endpunkte `POST /banking/fints/accounts/{id}/assign`, `POST /properties/{id}/bank-accounts`); alle Mandanten |
| Source status | Keine Rechtsnorm (Anhang C). Fachliche Umsetzung des Betreiberauftrags 29.09.2026 (kein Parallelbetrieb mit Immoware24, Buchhaltung je Objekt). Produktschutz: Rechtsträger je Kontoart nach 6.9.1 (`properties.services.ACCOUNT_OWNERS`), IBAN aus dem Umsatz wird nie automatisch freigegeben (M5-01) |
| Acceptance case | keine in Anhang D; Tests `apps/api/tests/integration/test_property_creditors.py` (Verknüpfen, Gewerk, Lösen, Filter, Kontaktabschnitt, Kreditor aus Umsatz mit IBAN `pending`, zweiter Aufruf legt nichts an, Nachziehen idempotent und nur mit Kreditorenrolle, 403, Mandantentrennung), `apps/web-crm/src/components/banking/BankSetupWizard.test.tsx`, `CreditorContactButton.test.tsx`, `apps/web-crm/src/components/properties/PropertyCreditorsPanel.test.tsx`, `apps/web-crm/src/components/contacts/CreditorPropertiesSection.test.tsx` |
| Implementation | `mhvp.properties.creditors` (Dienst), `mhvp.properties.routers_creditors` (`GET/POST /properties/{id}/creditors`, `PATCH/DELETE /properties/{id}/creditors/{id}`, `POST /properties/creditors/backfill`, `GET /contacts/{id}/creditor-properties`, `GET /banking/transactions/{id}/counterparty-contact`, `POST /banking/transactions/{id}/creditor-contact`). Rechte: `properties:read` lesen, `properties:update` schreiben und nachziehen, `contacts:read` Gegenpartei und Kontaktabschnitt, `contacts:create` plus `properties:update` für Kreditor anlegen. Die Gegenpartei wird über den IBAN-Fingerabdruck einer Kontaktbankverbindung (nicht abgelehnt) oder den exakten Namen erkannt; beides ist Hinweis, kein Beweis. Nachziehen verknüpft nur Kontakte mit Kreditorenrolle (gebuchte Ausgänge) oder mit Rechnung am Objekt; Zahlungen an Eigentümer oder Mieter erzeugen keine Verknüpfung. `open_invoice_amount` ist die Summe noch nicht gebuchter Rechnungen des Belegeingangs, keine offenen Posten der Buchhaltung (M11-08-Q1). Web: `BankSetupWizard.tsx`, `CreditorContactButton.tsx` im Buchungsdialog, `PropertyCreditorsPanel.tsx`, `CreditorPropertiesSection.tsx` |
| Change reason | Betreiberauftrag 29.09.2026: Bankkonto anlegen, mit Objekt verknüpfen, Umsätze je Objekt gegen Debitor oder Kreditor buchen, Kreditoren automatisch als Kontakte mit Reiter Dienstleister/Handwerker |
