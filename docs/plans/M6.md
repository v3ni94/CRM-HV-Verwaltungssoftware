# M6 Dokumente und DMS: plan and result

Status: backend done (2026-09-23). Source: MASTER-PROMPT 6.7, 6.9.5, 7.11 (S02, S04, S05), 11,
18 (M6), D43, D46, E05.
Acceptance: upload and link a document, mirror it to Paperless and Drive; letter from a template
on the HVM letterhead; full text search.

## Decisions

* Tables (migration 0006, all with RLS): `document`, `document_link`, `document_category`,
  `retention_profile`, `dms_connection`, `document_mirror`, `document_template`.
* Originals in the S3 object store under `tenants/<tenant>/documents/<id>` (ADR 0005), unchanged,
  with SHA-256. Upload limit and accepted types: A-016; content must match the declared type.
* Text: plain text and PDF text layer are indexed directly; scans and images are `pending` for
  OCR (Paperless). Search: `tsvector` (german) on title, filename and text plus trigram on title,
  with highlighted snippets. Embeddings (6.7 optional) follow with the AI gateway (M7).
* Links to contact, property, building, unit and contract; links with role original, evidence
  or generated cannot be removed.
* Retention (6.9.5, E05): no profiles ship (V17 open, M6-04). Deletion requires a released
  profile (four eyes: drafter cannot release), an expired `retention_until` and no hold; every
  refusal and deletion is an event. Documents mirrored to an external DMS stay locked until the
  mirror deletion exists (M6-03).
* DMS mirrors (11.1, 11.2): `DocumentStore` protocol with `PaperlessStore` (REST, token, tags
  `mhvp:tenant:<slug>` and `objekt:<nummer>`, correspondent, document type, asynchronous consume
  task resolved later) and `GoogleDriveStore` (Drive v3 REST, OAuth refresh token, object folder
  "NNN Ort, Straße Hausnummer" with subfolders 01 to 06). Connections per tenant, secrets field
  encrypted and write only, default off. Celery beat job `mhvp.documents.mirror` every minute
  with backoff 60 s to 24 h, then `failed`; manual re-queue endpoint.
* Letters (A-018): templates with Jinja2 placeholders in a sandbox, strict (missing value is an
  error), values escaped; versions keep old templates, only the active one is used. Placeholder
  namespaces `empfaenger`, `objekt`, `einheit`, `vertrag`, `gesellschaft`, `datum`, `felder`.
  Letterhead from tenant settings (company data, `branding.letter_band`, logo document); a
  GmbH/AG letter needs register court, number and management, else `MHVP-DOC-0004`. PDF via
  reportlab. Generated letters are filed and linked automatically (11.3); preview is not filed.
  Serial letters: one document per recipient in one transaction. Nothing is sent (M13).
* Default categories and the free letter template per tenant (A-017).
* HVM seed: letter band from the hvm-ci skill (section 5).

## Endpoints

`/documents` (upload multipart, search), `/documents/{id}` (read, patch, delete),
`/content`, `/links`, `/hold`, `/mirror`, `/document-categories`, `/retention-profiles`
(+ `/release`), `/dms-connections/{kind}`, `/document-templates`, `/letters`,
`/letters/preview`, `/letters/serial`. Permissions `documents:*`; DMS connections, categories,
templates and profiles need `tenant_settings:update`; caretakers have no document access.

## Result

* API: ruff, mypy strict, `alembic upgrade/downgrade/check`, full suite passed, coverage above
  90 %. New tests: `tests/integration/test_m6_documents.py` (upload, duplicates, search with
  snippet, links, download headers, rejected files, tenant isolation, permissions; retention
  lock, four eyes release, hold; letters with letterhead check, strict placeholders, escaping,
  template versions, serial letter all or none; mirror to Paperless and Drive against a fake
  server with failure, backoff and consume task), `tests/unit/test_m6_documents.py`.
* Visual check: page 1 of a letter rendered and inspected (band, fold marks, address field, info
  block, footer with register data).
* Not executed: mirroring against a real Paperless-ngx or Google Drive (no access, M6-01,
  M6-02); CRM screens for documents and letters (follow with the object screens).
