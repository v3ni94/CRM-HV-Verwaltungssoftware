# B03 Korrektur statt Überschreiben

| Field | Content |
| --- | --- |
| ID | B03 |
| Title | Korrektur statt Überschreiben |
| Scope | all ledgers (legal entity kinds hoa, rental_owner, sev_owner, manager); parallel operation, not leading until G1 |
| Source status | product standard of MASTER-PROMPT 7.1; no annex C norm claimed |
| Acceptance case | `test_m10_ledger.py` (API und direkter Datenbankzugriff) |
| Implementation | Gebuchte Sätze, Zeilen, offene Posten und Ausgleiche sind per Trigger unveränderlich; Storno mit getauschten Zeilen, Bezug, Grund, Grundcode, Urheber und Zeit; Festschreibung nur vorwärts, Storno dann mit offenem Datum. Package `mhvp.accounting`, migration 0010. Nachtrag 28.09.2026 (Migration 0232, ADR 0013): `services.reverse` nimmt einen Grundcode `ReversalReason` (`input_error`, `wrong_assignment`, `wrong_amount`, `wrong_date`, `duplicate`, `bank_return`, `run_reversal`, `automation_error`, `other`; Standard `other`), gespeichert als `journal_entry.reversal_reason_code` auf dem Stornosatz und im Ereignis `journal_entry.reversed`; der Freitext bleibt Pflicht. Der Grundcode ist Produktstandard für Zählung und Herabstufung im lernenden Buchhalter (M12-04), keine steuerliche oder rechtliche Einordnung. Bankseitig gilt: ein Bankumsatz, dessen Buchung storniert wurde, ist genau einmal neu buchbar (Storno plus Neubuchung); die alte Satznummer bleibt am Umsatz als Verlauf. Das Entscheidungsprotokoll `posting_decision` folgt derselben Regel (Anfügen, einmaliges Schließen, nie Löschen, Trigger `mhvp_posting_decision_guard`). |
| Change reason | M10 implementation, 23.09.2026; approval by operator pending (G1). Nachtrag 28.09.2026: Storno-Grundcode und Neubuchung nach Storno für den lernenden Buchhalter (Fahrplan M12 S0) |
