# M2-07 Löschen nur Administrator

| Field | Content |
| --- | --- |
| ID | `M2-07` |
| Title | Löschen nur Administrator: `*:delete` nur für `tenant_admin` und Plattformadministrator |
| Scope | Rollenmatrix `mhvp.core.auth.permissions` (alle Ressourcen mit Löschrecht: `contacts`, `properties`, `contracts`, `documents`, `ai`, `tickets`, `members`, `roles`, `api_keys`, `webhooks`, `audit`, `immoware`, `banking`, `accounting`), alle Mandanten |
| Source status | Keine Rechtsnorm im Quellenregister (annex C); Produktschutz, strengerer interner Standard, kein Rechtsanspruch |
| Acceptance case | keine in annex D; Tests `apps/api/tests/integration/test_m2_platform.py` (Rollenmatrix), `apps/api/tests/integration/test_m3_contacts.py::...` (403 für `clerk_no_delete`), `apps/api/tests/unit/test_permissions_delete.py` |
| Implementation | `mhvp.core.auth.permissions` (`_TICKETS`, `_MASTER_RWD` ohne `delete=True`), UI-Gate `apps/web-crm/src/components/contacts/ContactActions.tsx` (`canDelete`-Prop aus `contacts:delete`), `apps/web-crm/src/app/(app)/kontakte/[id]/page.tsx` |
| Change reason | Betreiberanforderung 25.09.2026: kein Mitarbeiter darf Datensätze löschen, nur `tenant_admin` (und der Plattformadministrator nach Mandantenwechsel, 5.1) |

## Regeln

- Kein System-Rolle außer `tenant_admin` und `administrator` (Alias, siehe `_ADMIN` in
  `mhvp.core.auth.permissions`) sowie der Plattformadministrator nach dokumentiertem
  Mandantenwechsel (`PLATFORM_SWITCH_PERMISSIONS`) erhält eine `*:delete`-Berechtigung.
- Alle bisherigen nicht administrativen Rollen mit Löschrecht (`standard`,
  `clerk_no_accounting`, `technical_clerk`, teils über `_TICKETS` und `_MASTER_RWD`) verlieren
  dieses Recht; sie behalten Lese-, Anlage- und Änderungsrechte unverändert.
- Soft-Delete- beziehungsweise Archivierungsaktionen, die keine endgültige Löschung sind
  (zum Beispiel `contacts:delete` als fachliches "soft delete" mit `deleted_at`, siehe
  `mhvp.contacts.services`), bleiben unter derselben Berechtigung `*:delete` geführt, solange
  kein separates, weniger einschneidendes Recht existiert; eine Aufspaltung in ein eigenes
  Archivierungsrecht ist ein offener Punkt, siehe `docs/OPEN_QUESTIONS.md`.
- Die API prüft ausschließlich über `require_permission` beziehungsweise
  `effective_permissions`; kein Endpunkt darf Rollen-Codes direkt abfragen, um Löschrechte
  zu vergeben.
- Die CRM-Oberfläche blendet Löschen-Schaltflächen aus, wenn `GET /api/v1/auth/me`
  `<ressource>:delete` nicht in `permissions` führt (Referenzimplementierung: Kontakte,
  `ContactActions`). Weitere Module (Tickets, Dokumente, Objekte, Angebote, Übergabe,
  Wissensdatenbank) sind nach demselben Muster zu ergänzen; nicht in diesem Durchgang
  umgesetzte Module sind ein offener Punkt, siehe `docs/OPEN_QUESTIONS.md`.
