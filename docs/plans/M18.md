# M18 Auswertungen und Exporte: plan and result

Status: evaluations, neutral journal export, DATEV batch header (M18-03) and the machine
readable audit export of 7.7 (A26, D55, rule M18-02) implemented; GoBD data carrier format
open (2026-09-26). Source: MASTER-PROMPT 7.5, 7.7, 18 (M18).
Acceptance: tax advisor imports the DATEV batch (open, M18-01); audit export per 7.7 scope
(implemented, not accepted; D55 test present); GoBD data carrier format (open, M18-01).

## Decisions

* `mhvp.accounting.reports`, migration 0018 (export_run): liquidity forecast 90 days per
  ledger with free funds, reserves, segregated deposits and expected in- and outflows apart
  (receivables are not liquidity); payments by debtor; revenue per revenue account; open
  items as of a date (M10); journal CSV with SHA-256 and export record.
* Tax advisor role: read and export accounting, no posting.
* DATEV endpoint refuses until the format data is specified.
* 25.09.2026 (M18-01, docs/rules/M18-03.md): the DATEV parameters (consultant number, client
  number, chart of accounts SKR03/SKR04, account length, fiscal year start month) moved from a
  fixed refusal to per tenant fields on `TenantBillingSettings` (migration 0069, shared with
  M13-04). `mhvp.accounting.reports.datev_csv` emits a DATEV EXTF Buchungsstapel header (format
  version 7, category 21) once all three required fields are set; CRM account numbers are
  emitted unmapped and the `ExportRun.note` records "Kontenzuordnung zu prüfen". The endpoint
  still refuses with MHVP-BILL-0004 otherwise.

* 26.09.2026 (A36, docs/rules/M18-04-datev-kontenzuordnung.md): operator maintained mapping
  of CRM account numbers to DATEV Sachkonten per tenant, optionally per ledger and valid from
  a date (`datev_account_mapping`, migration 0099; nothing preloaded, no SKR chart shipped).
  Endpoints `/api/v1/accounting/datev-mappings` (list, create, patch, delete, CSV import with
  preview, report of unmapped accounts per ledger and period); `accounting:update` maintains,
  `accounting:read` reads and reports. `reports.datev_csv` now writes the resolved DATEV
  account in "Konto" and refuses with `409 MHVP-BILL-0008` plus the list of missing accounts
  when any posted line in the period is unmapped; raw CRM numbers are never written and the
  `ExportRun.note` reads "Kontenzuordnung angewendet". CRM page Einstellungen, Buchhaltung,
  DATEV (`DatevMappingsAdmin`).

* 26.09.2026 (A26, D55, docs/rules/M18-02-pruefexport.md): `mhvp.accounting.audit_export`
  builds one ZIP per ledger (= legal entity) and period: CSV per table (accounts, entries with
  lines, reversal relations, opening balances, open items and settlements, approvals, events,
  master data and its audit log history, allocation keys and unit values, receipts), the
  linked original receipts as files below a configurable size limit (otherwise reference
  list with SHA-256), `export.json` and `index.csv`/`index.json` with row count, columns and
  SHA-256 per file. Recorded as `ExportRun` (format `audit_zip`, migration 0096 adds status,
  params, error, finished_at) with the ZIP as generated document of the legal entity.
  Endpoints `/api/v1/accounting/audit-exports` (create: inline up to 2.000 entries, else
  Celery `mhvp.accounting.audit_export_run`; list, status, download). Permissions:
  `accounting:read` for list and status, `accounting:export` for create and download. CRM:
  panel on the ledger's Auswertungen page. "GoBD" stays a reference to the 7.7 scope, not an
  assurance: no data carrier format, no description standard, no DATEV chart of accounts.

## Result

`tests/integration/test_m18_reports.py` (journal export unchanged; DATEV export blocked without
parameters, refused without account mapping, EXTF header with mapped accounts once
configured). `tests/integration/test_m18_datev_mapping.py` (A36: CRUD, CSV import preview and
apply, report per ledger and period including validity dates, export refused with the missing
list and written with a complete mapping, permissions, tenant separation);
`apps/web-crm/src/components/settings/DatevMappingsAdmin.test.tsx`. `tests/integration/test_m18_audit_export.py` (D55:
CSV contents against known postings, SHA-256 of the ZIP and of every indexed file, reversal
pair, packed receipt with matching hash, reference only mode above the limit, worker path,
permissions, tenant separation). `tests/unit/test_audit_export_csv.py` (CSV layout, cell
formatting, deterministic ZIP with index).

## Open points

M18-01 (partially resolved 25.09.2026: per tenant parameters and EXTF header; GoBD data carrier
format and its description standard remain open; the 7.7 audit export of 26.09.2026 does not
close this; the account mapping of A36 is in place but the actual assignments and the tax
advisor's acceptance of the batch layout are still to be entered and confirmed), M18-02. Audit export: master data history depends on which modules write
`audit_log` changes (contacts, properties, units do; contracts partly); approvals of dunning
and payments are outside the ledger scope; owner acceptance of the CSV layout with the tax
advisor is open.
