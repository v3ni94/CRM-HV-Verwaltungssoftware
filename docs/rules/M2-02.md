## Regeln

- Antragsteller und Genehmigender einer Freigabestufe sind verschiedene Personen
  (`MHVP-GATE-0002`); eine zweite Entscheidung über einen entschiedenen Antrag ist unzulässig
  (`MHVP-GATE-0003`). Das gilt unverändert, solange der Plattformschalter aus ist (Standard).
- Nur mit `gate_superadmin_bypass = true` darf genau der eine Benutzer mit
  `is_superadmin = true` (aktiver Plattformadministrator, höchstens ein Benutzer) einen
  eigenen Antrag genehmigen. Der Antrag trägt dann `four_eyes = false`, das Ereignis
  `release_gate.opened` die Nutzlast `superadmin_bypass = true`, das Änderungsprotokoll den
  Eintrag `four_eyes true -> false`, das Anwendungsprotokoll `release_gate_superadmin_bypass`.
- Keine Umgehung für Ablehnungen, für andere Plattformadministratoren, für API-Schlüssel, für
  Mandantenadministratoren, für andere Mandanten oder für fachliche Vier-Augen-Regeln.
- Den Schalter ändern nur Plattformadministratoren; jede Änderung wird mit Akteur, altem und
  neuem Wert und Version protokolliert. Kein Skript im Repository schaltet ihn ein.
- Die Umgehung schwächt die Kontrolle aus ADR 0003. Sie bleibt aus, bis der Betreiber sie
  einschaltet; Empfehlung: für produktive Mandanten aus lassen.
