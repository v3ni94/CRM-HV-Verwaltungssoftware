# M13-07 Buchungsentwurf des Verwalterhonorars je Buchungskreis

| Field | Content |
| --- | --- |
| ID | `M13-07` |
| Title | Eine freigegebene Honorarrechnung oder Gutschrift erzeugt je einen Buchungsentwurf beim Zahler und beim Verwalter, nur hinter G1 und nur mit hinterlegter Kontenzuordnung |
| Scope | `mhvp.accounting.admin_fee_posting` (`GET/PUT /accounting/admin-fee-posting-config`, `POST /accounting/admin-fee-invoices/{id}/posting-drafts`), Status `cancelled` und Filter `status` an `GET /accounting/admin-fee-invoices` (`mhvp.accounting.admin_fees`); Migration 0290; alle Mandanten, Gate G1 je Mandant |
| Source status | Fachliche Umsetzung nach 18 M13 (Verwalterhonorar), 6.9.1 und E01 (ein Buchungskreis je Rechtsträger), 7.1 B01 bis B09 und Regel 0.1.7. Keine Rechtsnorm zitiert. Kontenzuordnung und steuerliche Behandlung beim Zahler sind nicht festgelegt und werden vom Betreiber konfiguriert (OPEN_QUESTIONS P02-02, T04-01) |
| Acceptance case | `tests/integration/test_t04_admin_fee_posting.py` (vorgerechnet: 2 x 40,00 netto vierteljährlich, 15,20 USt, 95,20 brutto; Zahler Aufwand 95,20 an Verbindlichkeit 95,20; Verwalter Forderung 95,20 an Erlös 80,00 und USt 15,20; Gutschrift spiegelt beide Seiten; G1 geschlossen 403, nicht freigegeben 409, ohne Zuordnung 409 MHVP-ACC-0007, Verwalterbuchungskreis eines fremden Rechtsträgers 422 MHVP-ACC-0004, Rechte 403, anderer Mandant 404, Validierung 422, zweiter Aufruf idempotent) |
| Change reason | Lückenliste 30.09.2026, Befunde M13-05 (Rest: Status storniert) und M13-07 (Paket T04, Welle 5) |

## Regeln

- Ohne Zeile `admin_fee_posting_config` des Mandanten entsteht kein Entwurf. Es gibt keine
  Vorgabekonten.
- Die Verwalterseite liegt im Buchungskreis eines Rechtsträgers der Art `manager`; die
  Zahlerseite im Buchungskreis des Rechtsträgers `debtor_legal_entity_id` der Rechnung. Beide
  müssen verschieden sein (E01). Konten des Zahlers werden über die Kontonummer im jeweiligen
  Buchungskreis gefunden; fehlt eine, entsteht kein Entwurf.
- Beträge kommen unverändert aus der ausgestellten Rechnung (netto plus USt gleich brutto).
  Ist ein USt-Konto einer Seite hinterlegt und die USt ungleich null, wird sie dort getrennt
  ausgewiesen, sonst steht der Bruttobetrag auf Aufwand oder Erlös.
- Es entstehen nur Entwürfe (Status draft, Idempotenzschlüssel je Rechnung und Seite). Gebucht
  wird über den regulären Buchungsweg, der G1 erneut prüft. Ein gebuchter Satz wird nie
  geändert; Korrektur ist die Gutschrift mit eigenen, gespiegelten Entwürfen.
- Stornieren setzt den Status der Rechnung auf `cancelled` (neben `cancelled_at`); Dokumente
  einer stornierten Rechnung bleiben abrufbar.

## Ergänzung U01 (W05, 01.10.2026)

`PUT /accounting/admin-fee-posting-config` prüft die Kontoart der Verwalterkonten gegen den Kontenrahmen: Forderungskonto Kontoart Aktiv (asset), Erlöskonto Ertrag (income), Umsatzsteuerkonto Passiv (liability). Abweichungen werden mit 422 abgelehnt. Quellenstatus: Fachliche Umsetzung, keine Rechtsregel; die steuerliche Einordnung bleibt offen (T04-01). Abnahmefall: `test_fee_posting_drafts`.

## Ergänzung Review W79 (01.10.2026)

Die Zahlerkonten werden über Kontonummern je Buchungskreis des Zahlers aufgelöst und können beim PUT nicht geprüft werden. Beim Anlegen der Buchungsentwürfe prüft der Server die Kontoart: Aufwandskonto `expense`, Verbindlichkeit `liability`; Abweichung 409 `MHVP-ACC-0007`. Das Vorsteuerkonto des Zahlers bleibt ungeprüft (steuerliche Einordnung offen, T04-01). Abnahmefall: `test_fee_posting_drafts`.
