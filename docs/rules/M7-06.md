# M7-06 Tabellenimport deterministisch, KI nur für Spaltenzuordnung und Restzeilen, Produktschutz

| Field | Content |
| --- | --- |
| ID | `M7-06` |
| Title | Schneller Tabellenimport für `extract_contacts`: ein kleiner `map_columns`-Aufruf ordnet Spalten zu, danach werden Zeilen deterministisch in Python verarbeitet; nur mehrdeutige oder unlesbare Zeilen gehen noch an die KI |
| Scope | `mhvp.ai.table_mapper` (Spaltenzuordnung, Namens-/Adress-/Listen-Zerlegung), `mhvp.ai.gateway._run_fast_contacts`/`_process_chunks`, `mhvp.ai.tasks.ColumnMapping`/`ColumnMappingResult`, `AiTask.MAP_COLUMNS`, `mhvp.platform.models.TenantSettings.ai_fast_table_import`, Endpunkte `GET`/`PUT /api/v1/ai/fast-table-import`. | Source status | Keine Rechtsnorm (annex C); Produktschutz nach Betreiberauftrag 25.09.2026 (CSV-Importe über den KI-Chat sind bei vielen Zeilen zu langsam, da jede Zeile durch das Sprachmodell läuft) |
| Acceptance case | keine in annex D; Tests `apps/api/tests/unit/test_m7_fast_table_import.py` (Namens-/Adress-/Listen-Zerlegung, cp1252-Umlaute, leere Zellen), `apps/api/tests/integration/test_m7_ai.py::test_fast_table_import_only_sends_residual_rows_to_the_provider`, `::test_fast_table_import_falls_back_on_low_confidence_mapping` |
| Implementation | Migration `0067_ai_fast_table_import` (down_revision `0066`): fügt den Enum-Wert `map_columns` zu `ai_task` hinzu und die Spalte `tenant_settings.ai_fast_table_import` (`boolean`, Default `true`) |
| Change reason | Betreiberauftrag 25.09.2026: 864-Zeilen-CSV-Import dauerte 11 Chunks × 30 bis 60 Sekunden, weil jede Zeile durch das Sprachmodell lief |

## Ablauf

1. Ein KI-Aufruf `map_columns` (Tier `small`, Prompt `ai/prompts/map_columns/v1.md`) erhält
   Kopfzeile und höchstens fünf Beispielzeilen und liefert je Quellspalte ein Zielfeld
   (`ColumnMapping.target_field`), ob eine Kopfzeile vorliegt (`has_header`) und optional eine
   für alle Zeilen geltende Rolle (`default_role`).
2. Ist die Gesamt-Konfidenz der Zuordnung mindestens `table_mapper.MIN_CONFIDENCE` (0.6) und
   liegt eine Kopfzeile vor, verarbeitet `table_mapper.apply_mapping` jede Zeile deterministisch
   in Python: Namens-Zerlegung (Anrede, Titel, Vor-/Nachname, Firmenerkennung anhand von
   Rechtsformmarkern), Adress-Zerlegung (Straße/Hausnummer, PLZ/Ort), Telefon-/E-Mail-Listen,
   IBAN-Durchreichung, Rollen-Text oder `default_role`.
3. Zeilen, die eine Zelle mit mehreren Personen enthalten (z. B. "Hans und Erika Müller") oder
   ohne lesbaren Namen bleiben, werden als `residual` gesammelt und laufen, in Gruppen von
   höchstens `CHUNK_ROWS` (80) Zeilen, weiterhin durch die bestehende zeilenweise
   `extract_contacts`-Extraktion (`gateway._process_chunks`, aus dem bisherigen Chunk-Code
   extrahiert und jetzt von beiden Pfaden geteilt).
4. Die deterministisch erzeugten und die von der KI ergänzten Kontakte werden im selben
   `ContactsResult`-Format zusammengeführt (`source_row` bleibt erhalten); `contacts_preview`
   und `apply` sind unverändert.
5. Fortschritt (`ai_task_run.input_ref.progress.stage`): "Spalten erkannt", "n Zeilen
   verarbeitet", "m Zeilen an KI" (nur wenn Restzeilen bestehen), "Fertig".
6. Ist die Konfidenz niedriger als 0.6, fehlt die Kopfzeile, oder ist keine freigegebene Route
   für `map_columns` verfügbar (Budget, Freigabe), läuft der komplette Import unverändert über
   den bisherigen zeilenweisen KI-Pfad (`gateway._process_chunks` über alle Zeilen).
7. Mandantenschalter `TenantSettings.ai_fast_table_import` (Default `true`, `GET`/`PUT
   /api/v1/ai/fast-table-import`, Berechtigung `tenant_settings:update`): auf `false` verhält
   sich der Import wie vor M7-06.

## Offener Punkt

`extract_property` (Eigentümer-/Mieterlisten mit Einheiten, Verträgen, Zahlungen) ist von
diesem Produktschutz **nicht** erfasst und bleibt auf dem bisherigen zeilenweisen KI-Pfad: die
dortigen Zeilen tragen Einheiten-, Vertrags- und Zahlungsstruktur, die der Mapper hier nicht
abbildet. Eine Ausweitung ist ein separater Auftrag.
