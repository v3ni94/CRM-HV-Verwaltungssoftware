# M9 Oberfläche und Betrieb: plan and result

Status: done in the repository (2026-09-23); server rollout open (M9-01, M9-02).
Source: MASTER-PROMPT 3.5, 6.9.5, 16, 17, 18 (M9).
Acceptance: HVM works in parallel with Immoware24 on master data in the platform; backup
restore tested. The restore test passes locally and in CI; the parallel operation needs the
real import (M8-01) and the server (M9-01), see M9-05.

## Decisions

* Package `mhvp.workspace`: `models` (notification, calendar_entry, saved_filter; migration
  0009 with RLS), `services` (idempotent `notify`, derived calendar dates, maintenance
  reminders), `routers` (`/api/v1/workspace`), `tasks` (Celery `mhvp.workspace.reminders`,
  hourly beat), `ops` (`/api/v1/platform/ops/metrics`, platform admins only).
* Dashboard tiles follow the caller's permissions; no money figures until G1
  (`accounting: locked_until_g1`). Upcoming dates cover the last 30 and next 30 days.
* Global search over contacts, properties, units, contracts and documents, each part only
  with the matching read permission; RLS keeps tenants apart.
* Calendar: own and shared appointments plus derived maintenance and contract dates; derived
  dates are computed on read, never copied (no second source of truth).
* Bulk actions: contact tags and maintenance done only; all or nothing, permission checked,
  recorded as domain event. No bulk action with money effect exists (gates G1 to G5).
* Dark mode: system default, manual override per browser (`data-theme`), tokens stay neutral.
* Operations: `scripts/backup.sh` (pg_dump, age encryption mandatory unless explicitly
  allowed for tests, sha256, 30 days rolling), `scripts/backup-verify.sh` (restore into a
  throwaway database, revision and table checks), `scripts/deploy.sh` (`make deploy
  ENV=staging|prod`, backup before production migration, explicit tag confirmation for prod).
* Monitoring: counts per job (webhooks, DMS mirror, AI runs, notifications) as JSON with
  alert list and as Prometheus text.

## Result

* API tests: `tests/integration/test_m9_workspace.py` (dashboard by permission, search by
  permission and tenant, reminder idempotency, calendar visibility and ownership, filters per
  user, bulk all or nothing and permission, ops metrics admin only).
* Backup and restore: CI step "Backup and restore test (M9)" and local run.
* CRM: `/start`, `/kalender`, notification menu, theme switch, search over all areas, saved
  filters and bulk tagging in the contact list; Vitest in `Workspace.test.tsx`.
* Not executed: `make deploy` against a server (no server data, M9-01); age encryption path
  (tool not installed locally; unencrypted path used for the test with explicit opt in).
