# mhvp.integrations

External accounting/CRM integrations that are neither banking (`mhvp.banking`) nor a DMS
(`mhvp.documents`).

* Milestone: M13-lexoffice (docs/MASTER-PROMPT.md section 13.3).
* Specification: docs/integrations/lexoffice.md (binding endpoint list, source status,
  open points), `docs/rules/` (none registered yet, see module doc for the rationale).
* Status: settings page (`/integrations/lexoffice/config`, `/test`, `/runs`), explicit,
  protocolled export of invoices/contacts (`/export/invoices`, `/export/contacts`, gated by
  release gate G1 and the per tenant feature flag, default off) and explicit import of
  vouchers as `ReceiptDraft` (`/import/receipts`, no gate, no posting). No automatism: every
  export/import is one logged call, never a schedule or a trigger.
* `lexoffice.py`: `LexofficeClient` (httpx, fake transport in tests), calls only the
  endpoints listed in docs/integrations/lexoffice.md. It never builds the request body for a
  voucher or contact itself (the exact field schema is not fully documented, see that file's
  "Offene Punkte"); callers pass a finished, reviewed payload through unchanged.
* `models.py`: `LexofficeTenantConfig` (encrypted API key, feature flag), `LexofficeSyncRun`
  (protocol of test/export/import runs, shown as "letzte Läufe, Fehler"), `LexofficeExportLink`
  (dedup: one lexoffice id per exported CRM entity and tenant). Import dedup instead reuses
  `Document.source_system`/`source_id` (`source_system="lexoffice"`), so no separate import
  table is needed.
* Tests: `apps/api/tests/unit/test_lexoffice_client.py` (fake HTTP via `httpx.MockTransport`,
  monkeypatched transport, following the pattern of `mhvp.banking.finapi` tests). Router level
  integration tests (permission checks, gate G1, dedup across requests) are not yet executed;
  see the result report of the task that added this module.
* Money relevance: export is gated by release gate G1 (productive bookkeeping) in addition to
  the tenant flag; the AI/automation rule (0.1.6) does not apply here since export payloads
  are supplied by the caller, never generated by this module.
