# M15 Zahlläufe: plan and result

Status: implemented; file export behind G2 (closed) (2026-09-23). Source: MASTER-PROMPT 6.4,
6.9.9, 7.5, 18 (M15).
Acceptance: test or sandbox flows for approval change, double call, rejection, partial and
non execution, return and bank confirmation; file validity alone is not enough; G2.

## Decisions

* `mhvp.banking.payments`, migration 0015: payment_order (status per 6.9.9), payment_approval
  (snapshot hash, invalidated), payment_batch (message id, format, bank responses).
* Order from a posted, released invoice with confirmed IBAN, from a bank account of the same
  legal entity, never from a segregated deposit account; one open order per payable.
* Approval: two different users, platform admins excluded; a change of amount, payee, IBAN,
  date, invoice, bank account or purpose invalidates approvals.
* Export (pain.001) requires G2 (403 MHVP-GATE-0001) and a leading ledger (`leading_system = mhvp`, which requires G1); a comparison ledger never pays (13.1).
* Bank status: submitted and accepted do not settle; executed needs an imported debit on the
  ordering account (amount, E2E); repeated confirmation has no effect; partial debit settles
  partially; rejection keeps the payable; return reverses the payment posting.

## Direct debits pain.008 (A11, 26.09.2026)

* `mhvp.accounting.direct_debit`, `direct_debit_models`, `direct_debit_routers`, migration
  0093: direct_debit_run, direct_debit_order, direct_debit_approval (RLS); `sepa_creditor_id`
  on legal_entity and tenant_billing_settings (operator entry, no format check).
* Selection: open receivables of a ledger due by the collection date, resolved to the
  contract party's contact bank account with an active mandate (rule M3-02); every blocked
  item carries a reason and is never collected; revoked mandates are refused explicitly.
* Sequence type FRST/RCUR from the mandate history (RCUR once a run with the same bank
  account was handed out behind G2); one PmtInf per sequence type.
* Creditor identifier from the legal entity, fallback tenant billing settings, otherwise 422;
  collection date and lead days are mandatory parameters without defaults.
* Approval: two different users, platform admins excluded, snapshot bound, like pain.001.
* File: generated, structurally checked (no XSD in the repository) and filed as a document
  (`file_generated`); download only behind G2 (403 MHVP-GATE-0001), first download marks
  the run `exported`; nothing is transmitted to a bank.
* Pre-notification: one text draft per payer (amounts, collection date, mandate reference,
  creditor id) filed at the contact with a dispatch draft via `mhvp.communication.dispatch`
  (e-mail draft or postal record, never portal, never sent).
* Rule `docs/rules/M15-02-pain008.md`. Tests `tests/unit/test_pain008.py`,
  `tests/integration/test_m15_direct_debits.py`.
