# M1 Fundament: plan and implementation contract

Status: implemented, acceptance open (started 2026-09-23; see section 9). Source: `docs/MASTER-PROMPT.md` sections 0.1, 3, 4, 5.3, 6.9.14, 17, 18 (M1), 19.2, Annex E (E11, E12, E16).

This file is the binding contract for everybody working on M1 (humans and agents). If an
implementation needs to deviate, update this file first and record the reason.

## 1. Scope

In scope (M1 acceptance per section 18 plus start instruction 19.2):

1. Repository skeleton per section 17 (monorepo root = this repository).
2. `docs/MASTER-PROMPT.md` (verbatim copy of version 2.0 Final), `docs/OPEN_QUESTIONS.md`
   (section 19.1 V1 to V23, annex C.2 P01 to P05, new M1 questions), `docs/ASSUMPTIONS.md`,
   `docs/acceptance/D-cases.md` (annex D with milestone and gate mapping).
3. `CLAUDE.md` and `AGENTS.md` generated from one shared source `docs/AGENT_RULES.md`
   (rule 0.1.11: no contradicting parallel rule sets). CI checks they are in sync.
4. Docker Compose stack (`infra/compose.yaml`, `compose.dev.yaml`, `compose.prod.yaml`) with
   Traefik (dev only), PostgreSQL 16 with pgvector and RLS roles, Redis 7, S3 object storage,
   api, worker, beat, web-crm, web-portal, migration init job.
5. API skeleton (FastAPI) with health endpoints, RFC 9457 problem details, structured logging
   with correlation id, settings, database session helper with tenant RLS context, UUID v7,
   release gates G1 to G5 (fail closed), Alembic baseline, Celery worker with queues.
6. Frontend skeletons (Next.js 15) for web-crm and web-portal with health route, i18n (de-DE
   default), Vitest component test, Playwright smoke test; generated TypeScript API client.
7. CI (GitHub Actions): lint, types, tests, build, Trivy scan, OpenAPI drift check, migration
   check (`alembic check`), compose validation, agent docs sync.
8. ADR 0001 (stack and versions), ADR 0002 (tenant isolation), ADR 0003 (release gates),
   ADR 0004 (error format), ADR 0005 (object storage after the MinIO community archive).

Out of scope for M1 (later milestones, do not build now): tenant/user tables, auth, branding,
webhooks (M2); any domain table (M3+); observability stack Prometheus/Grafana/Loki (M9);
backups (M9); seed data (M2/M3); AI gateway (M7). `make` targets for these print the milestone
that delivers them and exit with status 2. No domain fields "auf Vorrat" (rule 0.1.2).

### 4.3 API endpoints delivered in M1 (base `/api/v1`)

* `GET /api/v1/health/live` returns `200` with
  `{"status": "ok", "service": "api", "version": "<semver>"}`. No dependency checks.
* `GET /api/v1/health/ready` returns `200` if all checks pass, else `503`, body
  `{"status": "ok"|"fail", "service": "api", "version": "...", "checks": {"<name>": {"status": "ok"|"fail", "latency_ms": <float>, "detail": <str|null>}}}`
  with checks `database`, `database_role`, `migrations`, `redis`, `object_storage`.
  `database_role` fails if the runtime role is superuser, has BYPASSRLS or owns tables
  (ADR 0002 enforced at runtime). `migrations` fails if the database revision is not the
  Alembic head. `detail` never contains hosts, credentials or stack traces.
* OpenAPI at `/api/v1/openapi.json`, docs at `/api/v1/docs`.
* Committed spec `apps/api/openapi.json` generated by `uv run python -m mhvp.openapi`
  (sorted keys, 2 space indent, trailing newline). CI fails on drift.

Errors: `application/problem+json` per ADR 0004 with fields `type` (`urn:mhvp:problem:<code>`),
`title` (German user text), `status`, `detail` (German), `instance`, `code`
(`MHVP-<DOMAIN>-<NNNN>`), `developer_message` (English), `correlation_id`, optional `errors`.
Every response carries `X-Correlation-ID` (accepted from the request if it is a valid UUID).

### 4.4 Release gates G1 to G5 (ADR 0003)

`mhvp.core.release_gates`: `ReleaseGate` enum with `G1` Produktive Buchführung, `G2`
Zahlungsveranlassung, `G3` Mietabrechnung, `G4` WEG-Abrechnung, `G5` Fremdmandanten. Resolver
protocol per tenant, default resolver keeps every gate closed. No environment variable or
setting can open a gate. Guard for FastAPI (`require_release_gate`) and for jobs/imports/bulk
(`ensure_release_gate_open`). Closed gate yields problem `MHVP-GATE-0001` (HTTP 403).
Persistence per tenant (who opened, when, evidence document, scope) arrives with the tenant
table in M2.

### 4.5 Web apps

* `GET /api/health` in each Next.js app returns
  `{"status": "ok", "service": "web-crm"|"web-portal", "version": "<semver>"}`.
* Home page (German): product name "MH Verwaltungsplattform", area "Verwaltung" (CRM) or
  "Portal", and a server rendered API status line using the generated client against
  `MHVP_API_INTERNAL_URL` + `/api/v1/health/ready` ("API bereit" / "API nicht erreichbar").
* No CI colors or logos are invented; neutral tokens until the CI values are released (V14).
* German UI texts avoid dashes as sentence punctuation (org style rule).

## 6. Migrations

* `apps/api/alembic/versions/0001_baseline.py`: function `app_current_tenant_id()`
  (`NULLIF(current_setting('app.tenant_id', true), '')::uuid`, STABLE), extensions
  `IF NOT EXISTS` for the trusted ones as a safety net. No tables.
* Helper `mhvp.core.db.rls.tenant_rls_statements(table)` returns the SQL to ENABLE and FORCE
  RLS and create two policies on `tenant_id = app_current_tenant_id()`, each with `USING` and
  `WITH CHECK`: permissive `tenant_access` and restrictive `tenant_isolation` (restrictive
  policies are ANDed, so a later permissive policy cannot widen access across tenants).
  Every future tenant table must use it.
* Migration 0001 revokes INSERT/UPDATE/DELETE/TRUNCATE on `alembic_version` from every role
  except the owner and fails with a clear message if the `vector` extension is missing.
* `alembic check` must report no pending autogenerate changes (CI).

## 7. Tests (rule 0.1.9, E12)

Backend (pytest, coverage for `mhvp.core` at least 80 percent):

* health live and ready (all ok, each check failing, 503, no secret leakage);
* problem details for 404, 405, 422, 500, gate closed; code format;
* correlation id propagation and rejection of invalid ids;
* UUID v7 version/variant bits, ordering of 10.000 ids, uniqueness;
* release gates: every gate closed for any tenant, missing tenant context is closed, no env
  override, FastAPI guard and job guard;
* integration (real PostgreSQL, marked `integration`, CI sets `MHVP_REQUIRE_INTEGRATION=1`
  so missing DB fails instead of skipping):
  roles have no superuser/bypassrls/createrole, app role owns nothing and cannot create in
  `public`, cannot `SET ROLE` migrator; RLS probe table created via the helper isolates
  tenants, returns nothing without tenant context, rejects cross tenant insert with
  `WITH CHECK`, app role cannot disable RLS; coverage guard: every table with a `tenant_id`
  column has RLS enabled, forced and the restrictive `tenant_isolation` policy; Alembic upgrade, downgrade,
  upgrade round trip; readiness against the real database;
* worker: Celery config (queues, acks late, prefetch 1, UTC), ping task eager.

Frontend: Vitest component test per app (status line renders German texts for both states),
route handler test for `/api/health`, Playwright smoke (home renders, `/api/health` ok).

Executed in the build environment:

* Backend: 103 tests pass, of these 32 integration tests against PostgreSQL 16 + pgvector and
  Redis (`MHVP_REQUIRE_INTEGRATION=1`); coverage 96 percent. `alembic check`: no drift.
* Frontend: 14 Vitest tests and 5 Playwright smoke tests pass.
* Native end to end run: migrations, bucket bootstrap (S3 simulated with moto server), API
  readiness with all five checks ok, Celery worker online and `mhvp.core.ping` answered via
  the Redis broker, web-crm standalone showing "API bereit".
* `docker compose config` valid for dev, prod and staging.

Not executed:

* `make dev` and all Docker image builds and the Trivy scan: Docker Hub blob downloads are
  blocked by the build environment egress policy (OPEN_QUESTIONS M1-07).
* GitHub Actions CI: not yet run at the time of this report; M1 counts as done only when CI
  is green (rule 0.1.9, 0.1.14).

Deviations:

* Section 18 M1 names MinIO; the dev/CI stack uses SeaweedFS because no maintained MinIO
  community image is available. Decision M1-01 (ADR 0005) is open; no production data before.
* Review hardening beyond the plan: runtime role must not be member of any role; readiness
  cached (single flight, 2 s TTL); SQL parameters hidden from logs; uvicorn trusts forwarded
  headers only from `MHVP_FORWARDED_ALLOW_IPS`; staging/prod refuse `change-me` secrets;
  job guard `release_gated()`.

Acceptance by the operator: open.
