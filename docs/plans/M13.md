# M13 Sollstellung und Verwalterhonorar: plan and result

Status: implemented for monthly full month components; fee as draft (2026-09-23). Source:
MASTER-PROMPT 6.4, 7.3, 7.5, 18 (M13).
Acceptance: monthly run for all properties under 2 minutes (small set passed, M13-05);
invoices valid as XRechnung (open, M13-04).

## Decisions

* `mhvp.accounting.receivables`, migration 0013: payment_type_account (revenue account per
  payment type and ledger), receivable_run (preview hash, totals), receivable_item (status
  ready, manual, blocked, posted, reversed; unique posted item per contract, component, month),
  admin_fee_setting.
* Preview computes items from contract payments and schedules; posting recomputes and refuses
  a stale preview; posting creates one receivable entry per item (debtor against revenue) with
  due date and idempotency key; reversal reverses all entries of the run.
* Proration, non monthly intervals, workday due rules, VAT and negative amounts are manual
  items (M13-01 to M13-03).
* Management fee: amounts per unit type, minimum and maximum, VAT rounding half up; result is
  a draft.
* 25.09.2026 (M13-04): `mhvp.platform.models.TenantBillingSettings` (migration 0069) holds the
  per tenant invoice prefix, VAT status (`unset`/`regelbesteuert`/`kleinunternehmer`), encrypted
  VAT ID and tax number (masked in the API to the last 4 characters), Leitweg-ID and the
  Kleinunternehmer note text; all nullable, nothing invented. `mhvp.accounting.numbering` holds
  `allocate_invoice_number`, allocating a gapless `PREFIX-JJJJ-000001` number under a locked
  `InvoiceNumberCounter` row (mirrors the journal counter, tested under concurrency). The
  Verwalterhonorar path (`POST /admin-fees/{id}/invoice-issue`) calls it and blocks with
  MHVP-BILL-0002/0003 when the VAT status or the tax data XRechnung needs is missing. The
  dunning fee invoice path is a separate agent's concurrent work; it is not wired here and gets
  its own call to `allocate_invoice_number`. `GET`/`PATCH /tenant/billing-settings` and a CRM
  section "Rechnungsstellung und Steuer" (Einstellungen/Mandant) let the operator enter the
  values. XRechnung XML generation and the official validator run (P05) are still open.
