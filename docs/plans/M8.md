# M8 Immoware24-Import: plan and result

Status: backend and CRM wizard done (2026-09-23). Source: MASTER-PROMPT 13.1, 6.9.10,
18 (M8), annex A.
Acceptance: full HVM stock (67 properties, 869 units, contacts, contracts) imported;
reconciliation against Immoware24 reports without open differences. Not reachable in this
repository: needs the real exports (M8-01) and the Immoware24 reference figures (M8-02).

## Decisions

* Package `mhvp.imports`: `models` (import_mapping, import_source_file, import_staging_row;
  migration 0008 with RLS), `fields` (platform target fields per report type, strict parsing
  of German numbers and dates), `services` (read xlsx/csv, stage, validate, apply, reconcile),
  `routers` (`/api/v1/imports/immoware24`).
* Column names of the exports are not specified (13.1): no built-in Immoware24 mapping. The user
  maps each target field to a file header and assigns source values of choice fields (value
  maps). Templates are versioned per report type and name.
* Flow: upload as document (DMS, original kept) → staging with raw rows → validate with a
  template (row status and errors) → test run in a rolled back savepoint → apply in one
  transaction as `import_run` (undo from M7) → reconciliation per file.
* Report types and order: properties, units (with MEA and valid from), contacts (with party),
  ownerships (WEG: ownership contract; rental: property owner), tenancies, payments (VAT rate
  from the file). Journal and bank transactions are stored as raw rows only (M8-03).
* Existing records are matched (property number, unit number, legacy contact id) and never
  overwritten: `unchanged` or `conflict` (A-021). Invalid values are errors, not guesses.
* All domain rules of M4 and M5 apply (creditor entity, periods, plausibility); a row that
  violates them is invalid with the platform's message.
* Permissions: `ai:create` plus `properties:create`, `contacts:create`, `contracts:create`.

## Nachtrag 26.09.2026: Abgleichbericht Parallelbetrieb (A68, M8-03)

* Package `mhvp.imports.reconciliation` (comparison), `reconciliation_routers`
  (`/api/v1/imports/reconciliation-reports`: list, create, JSON, CSV, column configuration) and
  `tasks` (Celery `mhvp.imports.reconciliation_all`, beat entry `imports-reconciliation-report`,
  time of day `MHVP_IMPORT_RECONCILIATION_TIME`, default 05:30). No migration: the report is an
  `import_run` with `source = immoware24:reconciliation` and the report as `summary`; the
  column configuration is stored as `import_mapping` rows named "Abgleichbericht (A68)".
* Source: newest staged file per report type `journal` and `bank_transactions` (or given
  `source_file_ids`), rows until `as_of` (default newest booking date). Per property and
  metric: `kontosaldo` per account (debit minus credit), `debitoren_op` (debtor accounts of the
  source against open receivables as of the date), `kreditoren_op`, `ruecklage` (credit balance
  of the reserve accounts), `bankstand` (last source balance against the newest statement
  closing balance, else sums of turnover), `zahlungen` (credits of the source period against
  bank transactions). Each line carries source, platform, difference (platform minus source),
  `deviates` and a German hint (property or account missing, no ledger, no statement balance).
* Read only: nothing is posted, settled or corrected; the account category comes from the
  platform ledger, never from invented ranges (rule 0.1.3). Column names are an assumption
  (A-047) and configurable per tenant.
* CRM: `/importe/abgleich` (list with CSV download, manual run with date, detail with
  "nur Abweichungen" filter, amounts `1.234,56 EUR`), link on `/importe`; BFF allow list
  extended; catalogues `ReconciliationReports` in de and en.
* Tests: `tests/integration/test_m8_reconciliation.py` (synthetic rows with hand computed
  differences, CSV, permission `ai:create`, tenant separation, column configuration, beat job),
  `tests/unit/test_m8_reconciliation_report.py`, `ReconciliationReports.test.tsx`.
* Open: real export column names and sign conventions (M8-01); `apps/api/openapi.json` and the
  generated client were not regenerated in this session (`make openapi`); the report run is
  listed under `/importe` like other import runs, an undo there has no effect (no items).
