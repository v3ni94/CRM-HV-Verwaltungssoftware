# M4 Objekte und Einheiten: plan and result

Status: backend done (2026-09-23). Source: MASTER-PROMPT 6.2, 6.9.1, 6.9.8, 18 (M4), annex A.2, A.3.
Acceptance: create a property with buildings and units; key values with period; as-of query;
property status.

## Decisions

* Tables per 6.2: `property` (number `NNN` unique per tenant, check constraint), `building`,
  `unit`, `allocation_key`, `unit_allocation_value`, `unit_vat_option`, `meter`,
  `meter_reading`, `property_owner`, `property_contact`, `service_provider_relation`,
  `property_bank_account`, `maintenance_item`; tenant level `catalog_entry`,
  `allocation_key_template`, `custom_field_definition`. All with RLS (migration 0004).
* Legal entity (6.9.1, E01) introduced now: `legal_entity` with kinds `hoa`, `rental_owner`,
  `sev_owner`, `manager`. A property `hoa`/`hoa_with_sev` gets exactly one GdWE entity (partial
  unique index), named "Gemeinschaft der Wohnungseigentümer <address>"; a rental owner gets an
  entity per owner party. SEV owner entities follow with ownership contracts (M5). Ledgers (M10)
  will reference legal entities.
* Bank accounts belong to a legal entity: HOA, reserve and HOA fee accounts only to the GdWE;
  rent and deposit accounts only to the landlord (rental or SEV owner); deposit accounts are
  `segregated` (check constraint, D56). The management type cannot change after creation.
* Quantities (areas, MEA, key values, readings, shares) are `NUMERIC(20,8)` (6.9.8; 6.2 still
  says 14,4 for key values, 6.9.8 takes precedence).
* Key values: periods of one unit and key never overlap (GiST exclusion constraint); adding a new
  value closes an open ended earlier value on the previous day. `as_of` returns the values valid
  on that date.
* Standard catalogues only from the master prompt: meter types (6.2, A.3), provider contract types
  and contact categories (6.2); allocation key template = annex A.2 list. Names are reference
  terms, no statement on allocability (7.2).
* Meter readings lower than an earlier reading are flagged `implausible`, never rejected.
* Property status: onboarding to active (needs a non fictional unit), active to terminated (needs
  `managed_to`); no way back.
* Unit VAT options are master data only; tax treatment needs a released rule (S01, D45).
* No fields in advance: creditor accounts (M10), billing periods and statement status (M17/M24),
  notice board (M21) are not created yet.

## Result

Backend tests pass incl. 4 new acceptance tests (keys with period, as-of, status, legal entity
account rules, catalogues, custom fields, caretaker read only). UI for properties follows with the
CRM screens (M9 scope, list and detail pages in the next UI iteration).
